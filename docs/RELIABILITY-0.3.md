# 0.3 可靠性修复记录

本轮先补复现测试，再修改代码。以下四项在修改前出现了实际测试失败：保存备注期间的新输入被覆盖、主数据文件缺失时覆盖有效备份、无操作重启替换历史备份、事务返回对象的后续修改影响内存状态。

## 已处理的问题

| 场景               | 处理方式与验证                                                                     |
| ------------------ | ---------------------------------------------------------------------------------- |
| 保存备注时继续输入 | 保存响应只确认当时提交的内容，后续输入继续作为草稿保留；浏览器延迟请求测试通过     |
| 中英文切换         | 草稿按任务与语言分开保存，不再将旧语言的内容写入新语言的缓存                       |
| 本地缓存写满       | 明确提示写入失败，当前会话保留草稿；切到其他页面后退出仍会提示未保存内容           |
| 主数据文件缺失     | 发现备份后停止初始化，不创建空工作台、不覆盖备份                                   |
| 正常重启/重复操作  | 无变化时不滚动备份；重复关联 PR 不再无故增加任务版本                               |
| 状态文件或设置损坏 | 保留损坏原件；仅在备份校验通过后提供明确的恢复入口                                 |
| 恢复与并发修改     | 有效主文件不会被恢复操作覆盖；更新版本的数据不会被当作损坏文件降级恢复             |
| 两个进程同时启动   | Windows 使用由系统持有的命名管道作为工作台写锁；过期记录不再引发读取/删除/创建竞态 |
| 启动或端口绑定失败 | 释放已获得的工作台锁，允许正常重试                                                 |
| 请求取消后退出应用 | 等待处理函数和元数据写入结束，再释放锁，防止下一进程提前进入                       |
| 取消切换工作台     | 用户取消关闭时不保存新目录，也不预先安排重启                                       |
| 设置写入失败       | 内存中的已提交设置保持原值；文件权限、空间不足等错误使用明确提示                   |
| 已有分支           | 可在未占用的本地分支上创建 worktree；失败回滚保留原分支及原有提交                  |
| 示例初始化中断     | 支持继续设置；已存在的任务不重复创建，无关文件不加入示例提交                       |
| 非法/过大请求      | 返回明确的 400/413 错误；权限问题不会被误当作会话失效重复提交                      |

## 数据格式升级

0.3 写入格式 2，用来保存 worktree 与分支的独立归属信息。格式 1 可读取；首次修改前保存原始 `state.v1.backup.json`。旧版应用不应继续打开升级后的数据目录。更高版本格式会明确要求升级，不提供降级恢复。

`state.backup.json` 和设置备份只覆盖元数据，不是源码、未提交文件或 Git 对象的完整备份。

## 发布范围

本轮交付 Windows x64 安装包，保留中英文和既有界面。代码签名、自动更新、其他操作系统的成品验证和真实团队长期试用仍待完成。测试覆盖不等于对所有未知环境作无故障保证。
