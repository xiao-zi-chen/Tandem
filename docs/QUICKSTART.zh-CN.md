# 快速上手

[返回首页](../README.zh-CN.md) · [English](QUICKSTART.md) · [全部文档](README.md)

同序将一个任务在多个独立本地 Git 仓库中的工作组织到一起。下面以同时修改前端和 API 的功能为例。

## 1. 安装并检查 Git

在[同序 0.4.0 发布页](https://github.com/xiao-zi-chen/Tandem/releases/tag/v0.4.0)下载 **Windows x64 安装包**。退出旧版本，运行安装程序，再打开同序。当前预览版安装包未签名，暂不提供自动更新。

需要已安装并加入 PATH 的 Git。在「设置」中可查看检测到的版本；如果不可用，请安装 [Git for Windows](https://git-scm.com/downloads/win)，重启同序后再检查。使用桌面版无需安装 Node.js 或 Python。

发布附件中包含 `SHA256SUMS.txt` 与 `release-info.json`。在下载目录打开 PowerShell，运行以下命令，将结果与发布的校验值对比：

```powershell
Get-FileHash .\Tandem-Setup-0.4.0-x64.exe -Algorithm SHA256
```

## 2. 体验示例，或连接自己的仓库

「打开示例工作台」会在本机创建两个真实 Git 仓库和三个任务。打开「订阅方案支持年付」任务，可以查看两个仓库的变更。示例用于演示 Git 工作流程，不是可以直接运行的完整前后端应用。

使用自己的项目时，进入「仓库 → 连接仓库」，用目录选择器选择已有的本地 Git 仓库，或粘贴完整路径；分别连接前端和 API 仓库。远端仓库需要先用原有 Git 工具克隆到本机。

如果经常使用同一组仓库，可以保存为「仓库组合」。下次创建任务时，再从组合中选择需要的仓库。

## 3. 创建任务工作区

选择「新建任务」，填写清晰的名称，例如 `新增年度订阅`，再选择仓库。

| 模式             | 适用情况                     | 实际行为                                                                          |
| ---------------- | ---------------------------- | --------------------------------------------------------------------------------- |
| **创建新工作区** | 希望给任务准备独立工作目录   | 为每个仓库创建 worktree；可以选择基线与新分支，也可以使用未被占用的已有本地分支。 |
| **接入已有工作** | 已经在现有工作目录中开始开发 | 原地关联所选目录，包含其中尚未提交的改动。                                        |

新建 worktree 时，可以给各仓库使用相同分支名，例如 `feature/annual-billing`；它们仍是各自仓库中的独立分支。使用已有分支时，该分支不能已被其他 worktree 检出。

选择「在 VS Code 中打开」，或者通过目录与复制路径操作进入惯用的编辑器。按项目要求安装依赖、配置端口和数据库。worktree 是 Git 工作目录，不提供运行环境隔离。

## 4. 集中审阅变更

进入「变更 → 全部仓库」，按仓库分组浏览任务中的文件。可以搜索仓库名，也可以搜索文件的新旧路径。

- 「工作区变更」展示本地变更，区分已暂存和未跟踪文件；「相对任务基线」展示相对记录基线的已提交变更。
- 切换统一或并排差异；长行可以换行，专注视图可以给代码留出更多空间。
- 在文件列表中使用方向键，或用上一个/下一个按钮切换文件。
- 大差异最初展示 500 行，可以点击「继续显示更多行」展开；Git 输出上限仍然适用。

重启后会保留差异布局与换行偏好。提交与推送继续使用原有 Git 工具。

## 5. 关联 PR 并交接

通过 GitHub 或原有工具创建 PR，再将 GitHub 链接关联到任务。需要时刷新状态；有可用的 `gh` 登录时优先使用，无法核实的状态保持「未确认」。此预览版尚未验证私有 GitHub 认证。

维护好任务备注和检查项。选择「导出交接单」，预览 Markdown 摘要后复制或通过系统对话框保存。分享前检查其中的本地路径和备注。导出不包含未提交的文件内容；需要交给别人接手的代码，请先提交并推送。

完成后可以归档任务。归档会将它从进行中的任务列表隐藏，保留文件、分支和 worktree；需要时可从「归档」恢复。worktree 清理请使用原有 Git 工具。

## 快捷操作与偏好

| 操作                    | 方法                                                                    |
| ----------------------- | ----------------------------------------------------------------------- |
| 查找任务                | **Ctrl+K**，搜索名称、仓库、分支或关联 PR；支持 `web #123` 这样的组合词 |
| 打开搜索结果            | 方向键选择，按 **Enter**                                                |
| 切换语言                | 侧栏底部的 **中文 / EN**                                                |
| 查看 Git 版本与数据位置 | 「设置」                                                                |
| 打开另一份同序数据目录  | 「设置 → 打开其他工作台…」                                              |

## 常见问题

| 问题             | 处理方式                                                                      |
| ---------------- | ----------------------------------------------------------------------------- |
| Git 不可用       | 在新终端中确认 `git --version` 可运行，再重启同序。                           |
| 分支已被占用     | 选择其他分支，或接入该分支已有的工作目录。                                    |
| 无法打开 VS Code | 选择「下载工作区文件」后用编辑器打开，或直接打开 worktree 目录。              |
| PR 显示未确认    | 检查链接、网络与已有 `gh` 登录；此状态不能用来判断 PR 已打开、关闭或合并。    |
| 数据目录被拒绝   | 选择空目录或已有的有效同序数据目录；普通的非空项目目录不能直接作为数据目录。  |
| 启动时提示恢复   | 阅读[数据与恢复](DATA.zh-CN.md)，保留现有数据目录，不要通过删除它来重置软件。 |

[反馈可复现的问题](https://github.com/xiao-zi-chen/Tandem/issues/new?template=bug_report.yml)时，请附同序版本、Windows 版本、Git 版本和操作步骤。截图与日志中请移除凭据、私人路径和源码。
